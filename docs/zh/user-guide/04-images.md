# 04 - 图片输入

> [English](../../en/user-guide/04-images.md) | **中文**

> 读完这页你能：发一张图片并得到关于它的回答。

## 前提

- 必须是 **Flash** 模型（`deepseek-v4-flash`，或名字里带 `flash` / `vision`）。
  `deepseek-v4-pro` 不接受图片，proJV 会直接不附加，而不是让你吃一个 400。
- 支持 JPEG、PNG、GIF、WebP。

## 怎么发

在消息里任意位置写 `@` 加路径：

```
这个 UI 哪里不对？@C:\shots\before.png
```

路径有空格要加引号：

```
@"D:\my shots\before and after.png"
```

一条消息可以带多张。

## 目录

`@C:\shots\`（以分隔符结尾）会展开成该目录**顶层**的图片，一条消息最多 8 张，
不递归。

## 限制

| 限制 | 值 |
|------|-----|
| 单张大小 | 约 30 MiB |
| 每条消息张数 | 8 |

图片以 base64 内容块发送，大图很费 token。`diagram_tool` 之类生成的 PNG 也可以直接 `@` 进来。

## 模型也能自己取图

在 Flash 模型下，agent 还多了一个 `view_image` 工具：不用你贴路径，它自己调
`view_image(paths=[...])`（比如截图工具刚写出的文件）。

API 只允许图片出现在 `user` 消息里，所以 proJV 不把像素塞回工具结果，而是登记一次
看图回合、结束当前轮，再补一条携带图片的合成用户消息，下一轮模型就能看到。

- 这条消息在聊天气泡里标 `(auto)`，落库时 `synthetic = 1`，回放历史时不会看起来
  像你自己打的。
- 这个工具必须单独调用。同一轮里的其他工具照样执行、结果也保留，但这一轮在它们
  之后立刻结束。
- `view_image` 和 `run_skill` 不能排在同一轮，后调用者会被拒绝。
- 越出工作区、不是图片、超过 8 张、单张过大，都会在发送前就被拒绝。
